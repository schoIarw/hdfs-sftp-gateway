# HFG 0.1.11 发布说明

## 重点变更

- 虚拟目录列表：列出某个目录时，网关会把该用户挂在当前目录下的其它虚拟映射一并列出，并在名字后加 `(v)` 标注，便于和真实 HDFS 目录区分。FTP 的 `LIST`/`NLST`/`MLSD` 与 SFTP 的 `readdir` 行为一致：

  ```
  ls /
  a
  b
  c (v)
  ```

- 标注不影响使用：`c (v)` 只是显示形式，客户端把该名字原样回传（`cd "c (v)"`、`get "c (v)/x.txt"`）时网关自动还原为 `/c`，进入目录、上传、下载都正常；直接用 `/c` 访问同样有效。
- 真实目录优先：当按上层映射算出的真实路径已经存在同名条目（例如根映射 `/` → `/h01`，同时存在虚拟目录 `/c`，而 HDFS 里已有 `/h01/c`）时，该虚拟映射失效并被遮蔽——列表中只显示真实目录 `c`（无标注），`/c` 与 `/c (v)` 下的上传下载都落在真实目录 `/h01/c` 上。
- 路径解析统一按“真实路径是否存在”判断遮蔽关系，读取、写入、列目录、重命名、删除的行为保持一致。

## 升级说明

1. 本次只有网关数据面逻辑变化，没有数据库结构变更；升级前仍建议备份管理库、日志库和 `/etc/hfg`。
2. 只替换 Gateway JAR 即可生效，Manager 无需变更（也可在同一维护窗口一起升级以保持版本一致）。升级后建议重启 Gateways 使新逻辑加载。
3. `(v)` 是显示标注：如果脚本按文件名做精确匹配，需要按去掉 ` (v)` 后缀的名字处理；按网关给出的名字直接操作（如 `cd`/`get`/`mget`）同样可用。
4. 通过网关自身无法创建与虚拟映射同名的真实目录（该名字的写操作属于映射目标），因此遮蔽场景对应“真实目录先存在、后加同名映射”。

## 介质

- `hfg-0.1.11-linux-x86_64-native.tar.gz`：Native JAR、Java 17 运行说明、systemd、Keepalived、Prometheus 配置和文档。
- `hfg-0.1.11-linux-x86_64-docker.tar.gz`：linux/amd64 Manager/Gateway 镜像、Compose、Keepalived、Prometheus 配置和文档。
- `SHA256SUMS`：两个独立压缩包的 SHA-256。
